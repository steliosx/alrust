| Y10 | Webhook batches (W-DL-1, 2026-10-01) | **Process every alert:** when one webhook call carries several alerts, each is handled independently, so a blackout, heartbeat, rate limit, rejection or error on one alert never drops the others. The HTTP status is the one the reference would have returned for the first alert not stored, so senders retry as they do today; the body lists each alert's outcome. (Specified as the first alert whose processing did not complete, since the reference can store an alert and then fail in a post-receive plugin; nothing is rolled back.) Other options offered: all or nothing; keep the reference behavior. Specified in `spec/security-fixes.md` |
